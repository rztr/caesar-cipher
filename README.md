Заготовка проекта первого модуля JavaRush University для группы 69 Warrant.
Полное задание лежит на платформе: [Проект модуля 1](https://javarush.com/quests/lectures/jru.module1.lecture51).

Программа шифрует текстовый файл сдвигом по алфавиту, расшифровывает его по известному ключу и подбирает ключ перебором, если ключа нет.

Я подготовил каркас: проект собирается, меню запускается, классы названы так же, как в задании.
Внутри методов стоят `TODO`, их и нужно написать.

## Как начать

1. Нажмите зеленую кнопку **Use this template** вверху этой страницы, затем **Create a new repository**.
2. Владелец репозитория - ваш аккаунт, имя любое, например `caesar-cipher`. Видимость **Public**, иначе я не смогу открыть работу.
3. Склонируйте свой новый репозиторий и откройте его в IntelliJ IDEA как Maven-проект.
4. Запустите `MainApp`. Должно появиться меню из четырех пунктов, а пункт `0` или слово `exit` завершают программу.

## Что уже есть

```
pom.xml                        Java 17, без зависимостей
text/input.txt                 пример текста для проверки
src/main/java/com/javarush/caesar/
    MainApp.java               алфавит, меню и вызовы режимов
    core/Cipher.java           encrypt и decrypt
    core/BruteForce.java       decryptByBruteForce
    service/Validator.java     isValidKey и isFileExists
    service/FileManager.java   readFile и writeFile
    exception/CipherException.java
```

Алфавит взят из задания, я дополнил его буквами `ё`, `й` и `ю`: в примере на платформе их нет, и текст с ними шифровался бы с дырами.
Заглавных букв в алфавите нет. Решите сами, что с ними делать: перевести текст в нижний регистр или расширить алфавит.

Порядок символов в алфавите не меняйте. Тогда я смогу расшифровать ваш файл своим ключом и проверить результат.

## Что написать

1. `Cipher.encrypt` и `Cipher.decrypt` - сдвиг по кругу. Символ, которого нет в алфавите, при шифровании пропускается, при расшифровке это ошибка.
2. `Validator` - ключ от 0 до длины алфавита минус один, файл существует.
3. `FileManager` - чтение и запись через `Path` и `Files` в UTF-8. Ошибку ввода-вывода превращаем в `CipherException` с понятным сообщением.
4. Режимы в `MainApp`: спросить файлы и ключ, проверить, обработать, записать результат.
5. `BruteForce` - перебрать все ключи и выбрать вариант, больше всего похожий на русский текст.

Статистический анализ в задании дополнительный. Если дойдете до него, заведите класс `StatisticalAnalyzer` и четвертый пункт меню.

Проверка готовой программы простая. Зашифруйте `text/input.txt`, расшифруйте результат тем же ключом и сравните с исходником. Затем взломайте зашифрованный файл перебором, ключ должен найтись сам.

## Как сдать

1. Работайте в отдельной ветке, например `feature/caesar`. Ветку `main` не трогайте до сдачи.
2. Коммитьте по шагам: каждый готовый класс отдельным коммитом.
3. Запушьте ветку и откройте Pull Request из `feature/caesar` в `main` **своего** репозитория.
4. Ссылку на Pull Request прикрепите к заданию «Проект модуля 1» в Google Classroom и нажмите «Сдать».

Замечания я оставлю прямо в Pull Request. Правки делайте в той же ветке, Pull Request обновится сам.
